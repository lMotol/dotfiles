# 実験研究レポート

読者が「何を比較したか」「何が変わったか」「どこまで原因を説明できるか」を、本文から理解し、資料で確かめられる記事を作る。日本語の本文・説明・図表キャプションを基本とし、コードの識別子や正式名称は原表記を保つ。

## 依頼に合わせる

- まず既存記事、集計元、実験スクリプト、実装を確認する。チャットの過去の説明を測定の証拠として代用しない。
- 執筆依頼だけで高コストの再測定を始めない。使える結果を整理し、不足する証拠は明記する。追加実験が依頼範囲なら、結論を左右する不足から補う。
- 既存の出力形式と保存場所を尊重する。Web記事の場合は [Web研究記事の構成](references/web-report.md) を読む。公開操作は利用する環境の手順とユーザーの依頼範囲に従い、このスキル自体を公開権限と解釈しない。
- 性能評価や生成コードを扱う場合は [測定と実装の対応](references/performance-evidence.md) を読む。特定のCPU、OS、比較方式数、反復数を全研究の必須条件にしない。

## 記事の組み立て

基本の流れは「研究上の問い → 比較方法 → 結果 → 原因の検討 → 限界・次の検証 → 再現資料」。この順を参考に、短い記事では節をまとめる。

冒頭には対象と主要結果を短く書く。改善例だけでなく、悪化・明確な差がない例も含める。実験を始めた経緯や作業日誌で結論を埋めない。

各結果について、次の対応を保つ。

| 要素 | 記載すること |
|---|---|
| 問い | 何の影響を切り分けたいか |
| 比較 | 基準方式、変更点、固定条件、実際に通った経路 |
| 観測 | 絶対値、差、単位、不確かさ |
| 根拠 | 対応するコード、測定指標、一次資料 |
| 解釈 | 支持される説明と、未検証の候補 |
| 限界 | この結果が適用できない条件 |

## 比較を読むための情報

- 方式名は冒頭で定義し、表・図・本文・コード見出しで統一する。内部のmode番号だけを読者に見せない。ユーザー指定の名称が紛らわしい場合は意味と例外を補足する。
- 主比較の全方式を同じ表・図で見せる。例えば通常呼出し・既存展開・提案展開の比較なら、通常呼出しを省いて展開同士の差だけを示さない。
- 絶対時間と基準に対する変化率を併記する。「既存方式より遅い」と「通常呼出しより遅い」を区別する。
- 補助対照は、何を切り分けるためか説明して主比較と区別する。必要な対照を見栄えのために捨てない。
- N、反復数、入力サイズなどは、何を数える変数か初出で説明する。読者が実験スクリプトを読まないと理解できない表記を避ける。

## 図表と文章

- 表は値を比較し、図は傾向とばらつきを把握するために使う。主張に対応する図表を置き、同じ情報の無目的な重複を避ける。
- 図表には対象、単位、集計方法、比較基準、良い方向を明示する。正規化では分母と計算方法を書く。誤差棒は何の区間か、何を独立な標本としたかを示す。
- 科学的な図は標準の描画ツールで再生成可能にし、用途に応じてSVGやPDFを保存する。描画用スクリプトと数値の出典を残す。
- キャプションは、本文を往復しなくても図表の意味が分かる説明にする。軸を狭めて微小差を大きく見せない。棒グラフの基点は原則0とする。
- 読者に役立つ一般的な用語を使う。独自の略称や名称で理解の負担を増やさない。既存の専門用語は出典や定義を添え、必要性が低ければ具体的な処理の説明に置き換える。
- 「重い命令」「最適」「大幅に改善」だけで説明せず、何が何個変わり、どの指標にどう表れたかを書く。

## 主張の強さを合わせる

観測事実、実装から確認した事実、原因に関する推論を文章で区別する。時間が短くなったことと、その原因を特定したことは別である。

- 命令数の減少だけで高速化の理由を断定しない。命令数が減っても時間が増えた例を隠さない。
- 差の区間が0を含むことを「同じ性能」と断言しない。今回の測定では明確な差を確認できなかった、と書く。
- 現在のソースから確認できる構造と、過去の開発者の意図を区別する。「なぜその設計を選んだか」は変更履歴やレビューで確認できる範囲にとどめる。
- 仮説に合わない結果は、仮説を見直す材料として扱う。次の実験は、競合する説明をどのように区別するかまで書く。

## 完了前の確認

主要な数値を集計元と照合し、式の分母、単位、符号、丸め、対象条件を確認する。全表のセルを手で写すより、同じ集計データから図表を生成する。

資料へのリンク、比較方式名、略語、コードと本文の対応を確認する。未測定・未検証の範囲を明示し、成功していないビルドや測定を完了扱いにしない。結論が変わる訂正では旧値と新値を混在させず、除外理由と影響を簡潔に残す。

ユーザーへの完了報告は、記事へのリンク、主要結果、重要な限界を短く伝える。再現に必要な詳細は記事と添付資料に置く。
