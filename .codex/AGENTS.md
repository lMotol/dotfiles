# 共通の基本ルール

## ルールと知識の配置

継続して使う指示や知識を追加・整理する際は、「適用範囲」と「常に必要か、特定の作業で必要か」で置き場所を選ぶ。

| 内容 | 置き場所 |
|---|---|
| 全プロジェクトに共通する基本方針 | `~/.codex/AGENTS.md` |
| プロジェクトをまたいで再利用する作業手順 | `~/.agents/skills/<skill-name>/SKILL.md` |
| 対象プロジェクトで常に守る基本ルール | `<project>/AGENTS.md` |
| 対象プロジェクトの特定作業に必要な手順 | `<project>/.agents/skills/<skill-name>/SKILL.md` |
| 言語仕様の補足、詳細設計、調査結果などの参照資料 | 対象プロジェクトの既存の文書置き場（例：`docs/`） |

既存の配置・命名・文書構成を確認してから変更し、ユーザーが指定した保存先を尊重する。この方針だけを理由に、依頼と無関係なファイルの移動や構成変更を行わない。

## プロジェクトの基本ルール

プロジェクトの `AGENTS.md` には、そのプロジェクトで作業する際に広く必要な指示を簡潔に記す。

- プロジェクトの目的と対象範囲。
- 採用言語・バージョン・実行環境など、作業に必要な前提。
- 守るべき設計上の制約や不変条件。
- 基本的なビルド・実行・検証コマンド。
- 関連する設計資料や、特定作業で読むべきスキルへの案内。

一部のディレクトリにだけ適用するルールは、必要に応じてそのディレクトリの `AGENTS.md` に置く。全体に適用する指示と局所的な指示を混同しない。

長い言語仕様の説明、詳細設計、実験ログ、特定作業の全手順を `AGENTS.md` に詰め込まない。判断に必要な要点と、詳細を読む条件・参照先を記す。

## 汎用スキルとプロジェクト固有スキル

スキルには、必要な作業で選択して使う手順をまとめる。常に適用する短い基本指示は `AGENTS.md` に置く。

- **汎用スキル**：研究の進め方、仮説・反証の扱い、比較実験、再現性、報告形式、図表の作り方、批判的な問答など。特定のコードベースや実験環境を前提にしない。
- **プロジェクト固有スキル**：対象の実装方式、固有の調査・デバッグ・検証手順、実際のコード経路や構成に依存する作業など。対象プロジェクトの `.agents/skills/` に置く。

例えば、helper inlineの研究では、証拠の扱い方や比較実験の進め方は汎用側、対象実装のABI・再配置・復帰命令の書換え・適用可否の確認手順はプロジェクト側に分ける。

一つのスキルに両者が混在する場合は、共通部分を汎用スキルに切り出し、固有側には差分と必要な参照を残す。同じ内容を両方へコピーして保守しない。分割先のスキルが実際に利用可能か確認し、不必要な依存関係は増やさない。

プロジェクト固有のパス、環境値、設計上の判断を、全プロジェクト向けの基本ルールや汎用スキルへ持ち込まない。逆に、他のプロジェクトでも使う方針を特定プロジェクトの制約として固定しない。

## 参照資料と重複の管理

詳細設計・仕様・実験結果は、プロジェクトの既存文書を正本とする。スキル専用の詳しい手順や例は、そのスキルの `references/` などに置ける。指示側には、どの作業で何を読むかを示す。

同じルールやスキルの正本は一つにする。複数プロジェクトで同じ専門スキルを共有する必要がある場合は、共有元と適用範囲を明確にし、参照やシンボリックリンクなどで重複更新を避ける。共有に伴う依存先が利用可能であることを確認する。

配置を変更した際は、参照切れ、同名スキルの意図しない重複、適用範囲の拡大がないか確認する。
